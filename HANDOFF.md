## Rough
- STAT MATH: loggedMiles() = clamped routePos() is THE miles figure — tripStats().done and spendTotals().miles both read it (they used tripProgress().miles, the last ARRIVED stop, so with Amarillo un-ticked Spend read $1.55/mi against 1,043 logged miles; now $0.75/mi, Wh/mi 887 → 429, projected $1,141 → $1,083; tripStats' perMi/whmi/proj are computed but nothing renders them). a day counts only with BOTH stamps and a span of 0–20h (MAX_DAY_MIN); every average is over those complete days, the day under way is reported beside them, and a rejected span is surfaced ("check its Departed / Arrived times") rather than absorbed. tripDayNow uses runDone (the unbroken run from Day 1) so a stray later stamp moves nothing. The stamp chip editor re-anchors an edited time to that card's own day, which is the only way to repair a mis-dated stamp.

- A Reset or double-tap takes ~1.2 s to settle exactly on 1×; until it lands the map keeps touch-action:none, so a one-finger drag pans instead of scrolling.

HARNESS RULE, learned the hard way at v83: a verify script must never retype a number that also lives in index.html. Running totals (charge counts, day kWh/$/min, spendTotals figures), frozen fixtures (before.json) and derived state ("day 3 is under way") all go stale the moment a charge is logged — one new charge broke 26 assertions across two suites. Instead reconcile (recompute the expectation from CHARGES/EXPENSES inside the harness and assert the app agrees), assert a delta the test itself causes, or assert structure/behaviour. A charge's OWN fields are safe to hard-code; rollups never are. Test it by injecting a fake charge on a new day plus a receipt in a new category and re-sweeping: nothing should fail — v84's real chg-018 then needed ZERO suite edits, which is the point. Second harness trap, same family: a duplicate-audit needle is a RENDERED VALUE, so a naive indexOf matches a shorter one inside a longer one — "6h 58m" (time at chargers) hit inside "16h 58m" (behind the wheel) and cried duplicate. verify-78's count() is now anchored on non-alphanumeric neighbours. Acceptance scripts (verify-84) are version-pinned and disposable by design; the durable regression suites must never be.
